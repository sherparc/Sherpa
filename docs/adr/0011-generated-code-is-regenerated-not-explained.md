# ADR-0011 — Generated code is regenerated, not explained: generator families and skill instead of agent

**Status:** accepted · **Date:** 2026-09-16 · **Decision:** Andrei · **Code:** `src/sherpa/scan/generators.py`, `src/sherpa/plan/rules.py`

## Context
While calibrating the plan rules on a large .NET monorepo, a migrations project ranked among the agent candidates
purely by churn — although almost all of its files are produced by `dotnet ef`. An agent that explains generated
output is worthless; what a developer needs to know is: generated from what, with which tool, with which
command. The pattern spans languages: protobuf stubs, Django/Alembic migrations, OpenAPI clients, GraphQL
codegen, ResX designers, `go generate`, JPA metamodels, snapshots, bundles.

## Decision
1. **Principle:** generated code is regenerated, not explained. The place of the knowledge is the generator —
   source, configuration, command — not the output.
2. **The scanner detects generator families** by path (T0/T1, no parser): per family, globs for output, sources
   and configuration plus the regeneration command. The model gets `generators[]` (one entry per family × owning
   module, `home` = common directory of the outputs) and `generated_files` per module and directory. User globs
   from `sherpa.toml [scan].generated` form the family `custom`.
3. **Plan:** units with ≥ 50 % generator output (`generated_share`) get no agent and no librarian and take no
   rank away; instead a **skill** `regenerate-<family>` is proposed at the `home`, with source, configuration and
   command as evidence. The owner doc stays. Floor: 5 generated files; configuration alone counts only for
   families whose output is not detectable by path (OpenAPI clients). Lockfiles are tool-managed: no skill.
4. **The hotspot exclusion stays broader** than generator output: lockfiles, images, data, resources (`NOISE`)
   are never hotspots but do not count as generated.

## Alternatives
- Only exclude generated modules (no proposals): rejected — the question "how do I regenerate this" stays
  unanswered, and that is exactly what AI agents get asked.
- Detection by file content (`// <auto-generated>` headers, `//go:generate`): deferred to T2 (M3b); paths cover
  the common families without reading blob contents.
- One regex alternation per family: rejected, 0.8 s on 15k paths; `GlobSet` (dict / `endswith` / literal
  pre-filter) needs 0.05 s.

## Consequences
- `codebase-model` schema v3 (`generators`, `generated_files`, `dirs[].authors_90d`).
- New families are one table entry in `FAMILIES` with a test in `tests/test_generators.py`.
- `apply` (M3) needs a skill template that renders `evidence.command`, `sources`, `configs`.
- A false-positive generator detection costs one unnecessary skill proposal, never a missing agent: the 50 %
  threshold requires that the output really dominates.
